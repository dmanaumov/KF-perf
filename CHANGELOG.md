## Не опубликовано

### Сравнение гипотез (кампаний)

- «Кампании»: у каждой строки галочка; отметьте 2–8 гипотез → «⇄ Сравнить». Выбор переживает сортировку, фильтр каналов и смену периода; «Сбросить» снимает всё.
- Попап «Сравнение гипотез»: таблица (расход, лиды, CPL, клики, CR — лучшее значение зелёным), три сравнения столбиками — сумма расхода, количество лидов, CPL — и динамика по дням линиями с переключателем Лиды / Расход / CPL и подсказкой по всем гипотезам на выбранный день. У каждой гипотезы свой цвет из проверенной на различимость палитры (8 цветов — отсюда лимит).
- «⬇ Сохранить в PDF» прямо в попапе: «Сравнение гипотез лидогенерации» — таблица, столбики затрат/заявок/стоимости заявки, графики заявок и затрат по дням. Формулировки нейтральные, как в основном PDF-отчёте. Файл `Hypotheses-<проект>_<с>_<по>.pdf`.
- Динамика: переключатель «По датам | По дню кампании». «По дню кампании» выравнивает гипотезы по старту: день 1 — первый день с показами/расходом/лидами у каждой (за всю историю, до 365 дней), ось «д.1, д.2…», в подсказке — день и дата, в легенде — дата старта. PDF сохраняется в выбранном режиме (`&axis=day`).
- Сервер: `metrics.compareItems`, `GET /api/projects/:id/compare` и `/compare.pdf` (`?from&to&items=[["platform","campaign_id"],…]`), `report.buildCompare/sendCompare`; `Charts.multiLine` и палитра `Charts.SERIES` в charts.js.

### PDF-отчёт «Эффективность лидогенерации»

- Кнопка «⬇ PDF-отчёт» в шапке проекта: отчёт за период и компанию, выбранные на «Сводке». В кабинете клиента — такая же кнопка рядом с выбором периода.
- Формулировки нейтральные — оценка эффективности форм лидогенерации, без «рекламы», «рекламных кампаний», «Instagram/Meta», «объявлений»: затраты на лидогенерацию, заявки, стоимость заявки, конверсия показ → переход → заявка, потоки заявок, источники заявок (Meta → «Формы лидогенерации»).
- Состав: шапка (проект, период, компания), 8 показателей с изменением к прошлому периоду, графики затрат и заявок по дням, «Эффективность по компаниям» (Все + каждая компания), «Эффективность по потокам заявок», источники (если их несколько), методика расчёта и отметка «Затраты указаны с НДС N%», если НДС задан. Суммы — в валюте проекта.
- Сервер: `src/report.js` (pdfkit, шрифт Manrope с кириллицей), `GET /api/projects/:id/report.pdf?from&to&ad`, `GET /api/client/:token/report.pdf?from&to`. Имя файла латиницей: `Leadgen-<проект>-<компания>_<с>_<по>.pdf`.
- Новые зависимости: `pdfkit`, `@expo-google-fonts/manrope` (package.json + package-lock.json) — Docker-образ пересоберётся сам через `npm ci`.

### Лента компаний со стрелками, валюта в шапке проекта, сброс кэша после деплоя

- Переключатель «Компания»: лента прокручивается стрелками ‹ › (видны, только когда есть куда листать), колесом мыши и свайпом; выбранная компания автоматически в зоне видимости; рядом — сколько компаний. Компании отсортированы «по-человечески» (2 раньше 10).
- В шапке проекта — выбор валюты (₽ / $ / € / ₸): меняет валюту всего проекта сразу, без захода в «Настройки».
- `server.js`: HTML отдаётся с `?v=<хеш>` у app.js/charts.js/guides.js/app.css и без кэша — после деплоя браузер сразу берёт новые файлы, а не закэшированные на час старые (из-за этого после прошлого релиза суммы оставались в ₽).

### Суммы в валюте проекта; ad_name = «Компания»

- Все суммы в кабинете команды и клиента показываются в валюте проекта (Настройки проекта → «Валюта»: ₽ / $ / € / ₸), а не всегда в ₽. Для $ и € — с центами до 1 000. Подписи полей плана и ручного ввода, тексты сигналов — тоже в валюте проекта.
- «Обзор»: суммы по проекту — в его валюте; итоги — в общей валюте проектов, при разных валютах у «Расхода» значок ⚠.
- Раскладка и переключатель по `ad_name` переименованы в «Компания» («Раскладка по компаниям», «Компания: Все | …»).

### НДС и курс для расходов Instagram / Meta

- Таблица расходов: поле «+ НДС %» рядом с «курс валюты ×». Расход = сумма из таблицы × курс × (1 + НДС/100); например, $ из Ads Manager × курс × 1,2. Выручка НДС не умножается.
- Подключение Instagram / Meta по API: те же поля «Курс валюты кабинета» и «НДС сверху на расход, %» в настройках канала.
- Курс и НДС применяются при загрузке: после изменения — «Сохранить и загрузить» (таблица перечитается целиком).

### Раскладка по объявлениям (ad_name)

- «Сводка» проекта: блок «Раскладка по объявлениям» — строка «Все (суммарно)» и по строке на каждое объявление (`ad_name`): расход, показы, клики, CTR, лиды, CPL, CR, доля лидов. Клик по строке — показать только это объявление.
- Переключатель «Объявление: Все | … » над KPI на «Сводке» и «Кампаниях»: фильтрует KPI, графики, каналы и таблицу кампаний (общий на проект). План/прогноз месяца остаётся по проекту целиком — при фильтре это подписано.
- «Кампании»: колонка «Объявление», если в данных есть ad_name.
- Google-таблицы: колонка `ad_name` / `Ad Name` / «Объявление» читается в обеих ролях (лиды и расходы), поэтому лиды и расход одного объявления сходятся в одной строке раскладки. Слово «объявление» больше не считается кампанией.
- БД: `stats_daily.ad_name` (добавляется автоматически при старте). `metrics.projectSummary(…, { ad })` + `byAd`, `adNames`; `GET /api/projects/:id/summary?ad=…`.
- Чтобы раскладка появилась у уже подключённых таблиц — нажать «Обновить из таблиц» (данные перечитаются вместе с ad_name).

### Google-таблицы: выгрузки Meta, несколько листов, курс валюты

- Таблица лидов/расходов принимает несколько ссылок (по одной в строке) и галочку «все листы таблицы» — вкладки читаются и складываются; пустой/служебный лист не валит загрузку.
- «Курс валюты ×» — для таблиц не в валюте проекта (отчёт Meta Ads Manager в $): расход и выручка умножаются на курс.
- Распознаются выгрузки Meta как есть: лиды из лид-форм (`created_time`, `campaign_name`, `platform` ig/fb, `lead_status`) и отчёт Ads Manager (`Day`, `Campaign Name`, `Amount Spent`, `Impressions`, `Link Clicks`). ID-колонки (`campaign_id` и т.п.) и «Cost per …/CPC/CPM» больше не перехватывают кампанию и расход.
- Дата с часовым поясом (`2026-09-28T22:37:52-05:00`) переводится в дату по Москве.
- Тестовые лиды (ячейка ровно «тест»/«test») не считаются.

### Кнопка «＋ Задача» в шапке проекта

- В шапке проекта (рядом с «Кабинет клиента» / «Настройки») — кнопка «＋ Задача»: открывает форму задачи сразу с этим проектом, работает на любой вкладке, включая «Сводку». На вкладке «Задачи» канбан обновляется сразу, счётчик «Мои задачи» в меню — тоже.

### Google-таблицы с лидами и расходами

- «Каналы и данные» → новый блок «📊 Google-таблицы с данными»: ссылка на таблицу лидов и ссылка на таблицу расходов + «Канал, если не указан». «Сохранить и загрузить» сразу читает таблицы и показывает итог (строк, спам/дубли, строки без даты).
- Новый коннектор `src/connectors/gsheet.js`: читает таблицу через экспорт в CSV (ключи не нужны, доступ «Все, у кого есть ссылка → Читатель»), понимает обычные и опубликованные ссылки, лист по `gid`. Колонки — по заголовкам: Дата (обязательна), Канал/Источник, Кампания, Расход, Лиды, Выручка/Сумма сделки, Показы, Клики, Статус. Заголовок может быть не в первой строке.
- Таблица лидов: 1 строка = 1 лид (или колонка «Лиды»); строки со статусом спам/дубль/тест/нецелевой не считаются. Таблица расходов: Дата + Расход. Из таблицы лидов берутся только лиды и выручка, из таблицы расходов — только расход/показы/клики, поэтому одну таблицу можно указать в обе роли без задвоения.
- Канал из текста («Яндекс Директ», «ВК», «Авито», «Instagram», «2ГИС», «Telegram», «Ozon», «WB», «Google»…) раскладывается по площадкам портала — графики, CPL, план/факт и разбивка по каналам считаются как для кабинетов. Нераспознанный канал → «Канал, если не указан», а его текст сохраняется как название кампании.
- Таблицы перечитываются целиком автоматически вместе с остальными каналами (строки, удалённые из таблицы, исчезают и из портала); пустая ссылка отключает таблицу вместе с её данными.
- `sync.js`: режим полной замены данных подключения (`replace`), площадка может задаваться построчно; планировщик обновляет Google-таблицы без кредов. `platforms.js`: источник `gsheet` (kind `source`, не попадает в списки каналов задач/журнала/плана).
- Инструкция «Как получить» для таблиц (`guides.js`), стили блока (`app.css`).

### Задачи Performance — в my.kontentferma

- Новый `src/routes/ingest.js`, подключён в `server.js` как `/api/ingest`:
  - `GET /api/ingest/tasks` — все задачи (кроме проектов в архиве) с названием проекта, справочник статусов и PUBLIC_URL;
  - `POST /api/ingest/tasks/:id/status` `{ status }` — смена статуса из my.kontentferma (галочка «выполнено»), `done_at` ставится/снимается как в обычном редактировании.
- Ключ — заголовок `X-Api-Key`: `KF_MY_API_KEY` (тот же общий ключ, что уже нужен для ролей из my) или `AUTOMATION_API_KEY`. Новых переменных не нужно.
